# Shared implementation contract

The Foundation-only Swift package module is `CookingCore` (iOS 17+, macOS 13+, Swift 5 language mode). The iOS app imports it. All IDs for recipes/steps are String; session/timer IDs UUID. Dates encode/decode using secondsSince1970 for backend; session persistence can use default Codable dates.

Core public types (root/UI consumes these):
- `CookingEvent: String, Codable, CaseIterable, Sendable`: chickenAddedToPan = chicken_added_to_pan, chickenFlipped, chickenRemovedFromPan, potPlacedOnStove, pastaAddedToWater, ingredientAdded, uncertain, noRelevantEvent with snake case raw values.
- `CookingObservation(event: CookingEvent, ingredient: String? = nil, confidence: Double, estimatedEventTimestamp: Date)`; Codable JSON timestamp is secondsSince1970 configured at transport.
- `RecipeStep`: id, title, fullInstruction, glassesInstruction, expectedEvents: Set<CookingEvent>, optionalTimer: TimerSpecification?, prerequisiteStepIDs: Set<String>, requiresContinuousAttention, allowsAutomaticProgression.
- `TimerSpecification(label: String, duration: TimeInterval)`.
- `Recipe`: id, title, subtitle, ingredients: [String], steps: [RecipeStep]. `SampleRecipes.all`, `.panSearedChicken`.
- `CookingTimer`: id UUID, label, associatedStepID String, startTime Date, duration TimeInterval, targetEndTime Date, isPaused Bool, isCompleted Bool, isDismissed Bool; `remaining(at: Date) -> TimeInterval`, `isExpired(at: Date) -> Bool`.
- `CookingSession(recipe: Recipe, now: Date = Date())`: id UUID, recipe, currentStepIndex Int, completedStepIDs Set<String>, timers [CookingTimer], revision Int, pendingObservation CookingObservation?, lastAction String?, currentStep RecipeStep, isFinished Bool. Core may add persisted internal fields needed for validation.
- `RecipeStateMachine` struct, `init(confidenceThreshold: Double = 0.85)`. mutating NOT necessary; funcs accepting inout session: `navigate(_: inout CookingSession, offset: Int)`, `markDone(_: inout CookingSession, now: Date)`, `apply(_: CookingObservation, to: inout CookingSession, now: Date, expectedRevision: Int? = nil) -> ObservationResult`, `confirmPending(_: inout CookingSession, now: Date)`, `rejectPending(_: inout CookingSession)`, `correct(_: inout CookingSession, toStepIndex: Int, now: Date)`, `undo(_: inout CookingSession, now: Date)` (optional one action snapshot internal). `ObservationResult` enum accepted, needsConfirmation, ignored(String). Navigation browses freely and must never complete steps or start timers; prerequisites remain enforced by markDone and observation validation. AI validity must reject stale inference after user changes (store revision checks too). Manual correction is explicit, confirms preceding steps, resets downstream evidence/timers, and preserves preceding timers exactly as they were.
- `TimerManager` static funcs `start(for: RecipeStep, in: inout CookingSession, now: Date)`, `pause(id: UUID, in: inout CookingSession, now: Date)`, `resume(id: UUID, in: inout CookingSession, now: Date)`, `dismiss(id: UUID, in: inout CookingSession)`, `extend(id: UUID, in: inout CookingSession, by: TimeInterval, now: Date)`. Duplicate timer per associated step prohibited. Timers persist as part of session.
- `SessionPersistence` struct `init(url: URL)`, `load() throws -> CookingSession?`, `save(_ session: CookingSession) throws`, `clear() throws` atomic.

App-owned protocol: `@MainActor protocol WearablesService: AnyObject`: `var status: WearableStatus { get }`, `var onStatusChange: ((WearableStatus) -> Void)? { get set }`, `var onFrame: ((CameraFrame) -> Void)? { get set }`, `var onNavigation: ((Int) -> Void)? { get set }`, `func connect() async throws`, `func startMonitoring() async throws`, `func stopMonitoring() async`, `func handleOpenURL(_ url: URL) async`, `func render(_ model: GlassesViewModel) async`. `WearableStatus` struct: connection: String, camera: String, isMonitoring: Bool, canRenderOnGlasses: Bool, detail: String. `CameraFrame`: timestamp Date, jpegData Data, luminance [UInt8] (32x32 analysis image). App defines `GlassesViewModel` compact step/timer/action data later. DAT agent owns iOS/Services/MetaWearablesService.swift and docs/DAT_0.9.0.md only initially. Root owns protocol, mock, camera image conversion, store, UI and Xcode project.

Backend contract `POST /v1/cooking/observe`: JSON `{recipe: {id,title}, step: {id,title,fullInstruction}, expectedEvents: [snake_case], frames: [{timestamp: number, jpegBase64: string}]}`. Response `{event: snake_case, ingredient?: string, confidence: number, estimatedEventTimestamp: number}`. Bearer token from runtime client input, Gemini key backend environment only. Gemini model `gemini-3.5-flash`. Reject unknown enums, oversized input, malformed timestamps. Bounded frame count/size and reasonable sequence time span. No server frame retention/logging. HTTP server Node built-ins with tests using node:test, no dependency needed. Root implements matching Swift DTO/service and frame processor. Backend agent owns backend/ and docs/BACKEND.md.
